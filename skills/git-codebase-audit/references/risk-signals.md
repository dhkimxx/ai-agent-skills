# Git 위험 신호 해석 가이드

## 1. 변경 빈도 상위 파일

원문 명령:

```bash
git log --format=format: --name-only --since="1 year ago" | sort | uniq -c | sort -nr | head -20
```

이 지표는 최근 1년 동안 가장 자주 바뀐 파일을 보여준다.

- 상위 파일은 요구사항 변화가 많거나 설계가 불안정한 지점일 수 있다.
- 팀이 자주 고치지만 소유를 꺼리는 파일이라면 구조적 부채일 가능성이 높다.
- 생성 파일, 락 파일, 대규모 포맷 변경 파일은 별도로 걸러서 봐야 한다.

## 2. 기여자 분포

원문 명령:

```bash
git shortlog -sn --no-merges
```

이 지표는 비병합 커밋 기준 작성자 분포를 보여준다.

- 상위 1명이 60% 이상을 차지하면 버스 팩터 위험 신호로 본다.
- 최근 6개월 기준 상위 기여자 활동이 없다면 유지보수 공백 가능성이 있다.
- 전체 기여자는 많지만 최근 활동 작성자가 소수라면 지식 단절이 진행 중일 수 있다.

주의:

- squash merge 전략은 실제 작성자보다 병합자 중심으로 흔적이 남을 수 있다.
- 봇 계정이 상위권이면 실제 사람 분포와 분리해서 해석해야 한다.

## 3. 버그 집중도

원문 명령:

```bash
git log -i -E --grep="fix|bug|broken" --name-only --format='' | sort | uniq -c | sort -nr | head -20
```

이 지표는 버그 관련 키워드가 달린 커밋에 자주 등장하는 파일을 보여준다.

- 커밋 메시지 품질이 낮으면 정확도가 떨어진다.
- 그래도 대략적인 결함 밀도 지도로는 충분히 유용하다.
- 변경 빈도 상위 파일과 겹치는 파일은 우선적으로 읽는다.

권장 우선순위:

1. 변경 빈도 상위 5개와 버그 상위 5개가 겹치는 파일
2. 버그 비중은 높지만 최근 변경이 줄지 않은 파일
3. 여러 작성자가 번갈아 고치는 파일

## 4. 월별 커밋 추세

원문 명령:

```bash
git log --format='%ad' --date=format:'%Y-%m' | sort | uniq -c
```

이 지표는 팀의 개발 리듬 변화를 보여준다.

- 완만하고 일정한 흐름은 비교적 건강한 신호다.
- 6개월 이상 지속 감소하면 동력 저하나 유지보수 모드 전환을 의심한다.
- 짧은 급증 뒤 긴 정체가 반복되면 배치형 릴리스 패턴일 수 있다.
- 특정 시점의 급감은 핵심 인력 이탈이나 우선순위 변경과 연결될 수 있다.

## 5. 긴급 대응 신호

원문 명령:

```bash
git log --oneline --since="1 year ago" | grep -iE 'revert|hotfix|emergency|rollback'
```

이 지표는 릴리스 안정성의 표면 신호다.

- 연간 몇 건 수준은 자연스럽다.
- 몇 주 간격으로 반복되면 테스트, 검증, 배포 절차를 다시 봐야 한다.
- 결과가 0건이어도 안전하다고 단정하지 말고 커밋 메시지 관례를 함께 확인한다.

## 결과를 왜곡하는 대표 요인

- `package-lock.json`, `poetry.lock`, 생성 산출물처럼 자동 변경이 잦은 파일
- 대규모 리네임이나 포맷터 일괄 적용처럼 의미 없는 churn
- 모노레포에서 특정 하위 프로젝트만 활발한 경우
- 봇 계정 또는 릴리스 자동화 계정
- `fix`, `bug`, `hotfix` 같은 키워드를 거의 쓰지 않는 커밋 문화

## 권장 보고 방식

최종 보고는 아래 순서를 지키는 것이 좋다.

1. 분석 기간과 저장소 범위를 먼저 명시한다.
2. 상위 churn 파일과 bug hotspot을 표로 제시한다.
3. 겹치는 파일만 다시 추려 "가장 먼저 읽을 파일"로 제안한다.
4. 기여자 집중도와 최근 활동 공백을 별도 단락으로 설명한다.
5. 활동 추세와 긴급 대응 신호를 근거로 팀/배포 리스크를 정리한다.
