# korean-tech-writing

> 한국어 기술문서를 쓸 때 따르는 작성 규칙.
> 문서 유형(6종) · 낯선 용어 풀이 패턴 · 문체·표기 규칙 · 발행 체크리스트를 담았습니다.

- **설치**: `npx skills add dhkimxx/ai-agent-skills --skill korean-tech-writing`

## 언제 쓰나

- 튜토리얼·하우투·레퍼런스·설명·교재·브리프를 새로 쓸 때
- 기존 한국어 문서를 고치거나 리뷰할 때(번역투, 용어 일관성, 문장 길이)
- PDF·이미지로 발행하기 전 점검이 필요할 때

## 구성 파일

| 파일 | 역할 |
|---|---|
| `SKILL.md` | 작성 규칙 본문 — 3원칙, 유형 6종(+1줄 골격), 용어 패턴 A~H, 문체·표기, 글리프 함정, 작성 프로세스 |
| `checklist.md` | 발행 전 체크리스트 — 공통 13항 + 유형별 + 출력 점검 |
| `references.md` | 출처 4계층(용어 표준·스타일 가이드·방법론·도구) + 규칙↔출처 매핑 |

## 핵심 규칙 (맛보기)

- **독자 먼저**: 첫머리에 독자 수준·선행 지식·읽는 시간을 밝힌다
- **쉬운 말 먼저, 용어는 병기**: `멱등성(idempotency)`처럼 첫 등장에서 풀어쓴다
- **문제 → 해결**: 기법보다 문제를 먼저 보여준다
- **문체**: 능동태 · 현재 시제 · 2인칭 · 조건 먼저 → 지시 나중
- **발행 전**: 소리 내어 읽기 + 초보자 리뷰어 + 글리프 검사

## 사용 예

```
이 API 변경 사항을 팀에 공유할 하우투 문서로 정리해줘.
```

에이전트가 유형을 고르고(하우투), 골격에 맞춰 쓰고, `checklist.md`로 자체 점검합니다.
